# Коммит и пуш

Зафиксировать изменения в git и отправить в `origin`.

## Порядок

### 1. Осмотреть изменения

Одной командой:

```bash
git status --short --untracked-files=all
git diff --stat
git diff --staged --stat
git log --oneline -5
```

Из вывода понять: что изменилось, есть ли уже проиндексированное, каков стиль сообщений в истории.

### 2. Проверить документацию

`.claude/CLAUDE.md` требует обновлять документацию в том же изменении, что и код. Перед коммитом проверить:

- изменился состав или назначение подсистем — правится `docs/code_map.md`;
- изменился публичный API — правится документ подсистемы в `docs/<subsystem>/`.

Документация разошлась с кодом — сообщить об этом и предложить дописать **до** коммита, а не коммитить расхождение.

### 3. Отобрать файлы

Индексировать только то, что относится к задаче.

Не коммитить без явной просьбы:

- артефакты сборки, каталоги IDE, временные файлы;
- секреты: ключи, токены, пароли, `.env`;
- крупные бинарные файлы;
- посторонние изменения, не связанные с задачей.

Найдено нежелательное — предложить дополнить `.gitignore`.

### 4. Сообщение

Формат:

```text
<Краткая суть в повелительном наклонении, до 72 символов>

<Пустая строка, затем — почему это сделано, если неочевидно>

Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
```

Правила:

- язык сообщения — как в истории репозитория;
- заголовок отвечает на «что изменилось», тело — на «почему»;
- пересказ диффа в тело не переносится: дифф читается из git;
- требование «нет лишних слов» из `.claude/CLAUDE.md` действует и здесь.

Многострочное сообщение передавать через heredoc:

```bash
git commit -q -F - <<'EOF'
Заголовок

Тело.

Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
EOF
```

### 5. Запушить

```bash
git push
```

Ветка новая — `git push -u origin <branch>`.

Push отклонён из-за расхождения с удалённой веткой — не форсировать. Показать причину и спросить.

### 6. Отчитаться

Назвать хеш коммита, ветку и состав изменений. Push не прошёл — сказать прямо и привести вывод.

## Границы

- Не коммитить в `main`, если задача явно относится к ветке: сначала предложить создать ветку.
- Не использовать `--no-verify` и не отключать подпись. Hook упал — разобраться с причиной.
- Не делать `--amend` уже отправленного коммита.
- `push --force` — только по явной просьбе; предпочитать `--force-with-lease`.
- Пустой рабочий каталог — сообщить, что коммитить нечего, и остановиться.
